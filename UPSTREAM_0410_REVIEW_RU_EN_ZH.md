## RU

### Решение

Сразу предусмотреть совместную работу всех наших модулей, но подключать их по одному через существующие механизмы Dewiar. Основу составляют штатные Plugins, Skills, MCPManager, TaskManager, Recall и канал событий. Для недостающих возможностей нужен небольшой версионируемый адаптер. Создавать второй набор задач, индекс памяти или новый агентный framework не требуется.

Принятие наших изменений автором не является зависимостью проекта MS8AT. Автору предлагаем отдельные воспроизводимые проблемы и небольшие функции. Codex, Human Memory, политика локальных моделей и связь с AI20 остаются опциональными дополнениями.

### Минимальные точки подключения — проект, ещё не готовый API

1. **Выбор исполнителя.** Назначение + явный выбор человека + разрешённые профили + проверенные возможности → один профиль или понятный отказ. Сохранять привязку для основного ответа, самопроверки, перевода и обучения. Исчезнувший профиль не заменять молча.
2. **Источник контекста.** Task ID + revision + разрешённая область + лимит объёма + отмена → ограниченный пакет с источниками. Источник можно выключить. Отсутствие разрешения означает отсутствие чтения. Контракт не зависит от Codex.
3. **Наблюдение.** Версия, готовность, текущие операции, время последнего события и безопасные коды ошибок. В первом варианте — только чтение, без текстов разговоров, токенов и запуска проверки модели.
4. **Описание адаптера.** Версия контракта, проверенная база Dewiar, зависимости, разрешения, обязательные тесты и возможность отключения. Неизвестная база запрещает автоматическое применение.

Human Memory пока жёстко связан с именем MCP-сервера и отдельным маршрутом подготовки контекста. Штатные плагины дают серверам имена с префиксом плагина. Нужна явная привязка источника и отдельный режим «только источник контекста»: установка обычного MCP сама по себе не обеспечивает область чтения задачи.

Heartbeat не следует реализовывать заданием модели по расписанию: штатные plugin jobs запускают работу помощника. Проверка состояния должна быть пассивной и не расходовать запросы модели.

AI20 предлагается подключать клиентом к существующему Manager → Router → исполнитель. Dewiar будет хранить внешний ID и показывать состояние; повторная очередь и второй владелец исполнения не нужны. При неизвестном исходе сначала выясняется результат. Текущее состояние AI20 в этом разборе не проверялось.

### Что можно предложить автору по одному

1. **Уникальная папка для каждой задачи.** В оригинале [tasks.py:384](https://github.com/dwr-git/dewiar-app/blob/ade7a0f0cb3cee7ff6f8cdc01c46a02e64101f61/core/tasks.py#L384) путь включает только минуту и заголовок. Два одинаковых названия в одну минуту получают одну папку: второй state перезаписывает первый, удаление второй задачи удаляет общую папку. Синтетический тест воспроизвёл это на 0.41.0; наша версия с ID в имени папки прошла проверку. Это самостоятельная небольшая правка.
2. **Удалён выбранный профиль модели.** Показать ошибку и предложить новый выбор вместо скрытого перехода на активную модель. Это не требует всей панели «Мозги» и нашей эвристики.
3. **Диагностическое подключение только для чтения.** Внешнему CLI достаточно статуса; не нужен полный UI-канал. Начать с одной команды статуса и ограниченного handshake.
4. **Ограниченное восстановление контекста.** Оригинал уже сокращает историю. Наш дополнительный шаг сокращает системную подсказку/инструменты. До предложения проверить сохранение доступа к результатам уже запущенных частей.

Ошибка папок отправлена отдельно как [issue #12](https://github.com/dwr-git/dewiar-app/issues/12). Остальное — очередь отдельных предложений, не новый большой PR. Вопросы #10 и #11 повторно не создаются.

### Что пока не готово

- На нашей 0.40.1 синтетический тест выявил потерю индивидуальной локальной привязки в фоновом обучении: при включённом learn и выключенном общем tasks.local_only мог выбираться общий профиль. Реального запроса модели не было. До исправления нельзя обещать, что локальная задача и все производные операции всегда останутся локальными.
- Для обучения по нескольким задачам нужна политика разделения записей по разрешённому исполнителю/области. Передать только профиль последней задачи недостаточно.
- Общий источник контекста и режим доступа только через него ещё предстоит реализовать и проверить. Нынешние тесты отдельного Human Memory не подтверждают эти будущие возможности.
- AI-доктор не должен переписывать код или повторять действие с неизвестным исходом. Он применяет ограниченные проверенные варианты восстановления; исправление исходников идёт отдельным патчем.
- Список моделей и короткий probe не доказывают качество длинной задачи. Результаты проверок контекста и инструментов должны иметь срок актуальности.

### Перенос с 0.40.1 на 0.41.0

В оригинале изменилось 87 файлов. С нашим 55-файловым runtime-слоем пересекаются семь:
`core/engine_commands.py`, `core/settings.py`, `ui/app.py`, `ui/hud.html`,
`ui/settings.html`, `ui/studio/brain.js`, `ui/studio/tasks.js`.
По полному дереву пересечений 11, включая Android, README и списки тестов.
Это пересечения изменений, а не результат merge и не доказанные конфликты.

Сохранить новые игры/блокнот, переключатели «Возможности», миграцию настроек и закрепление задач.
Официальный Windows-установщик заменяет каталог app; пользовательские плагины находятся отдельно в CONFIG_DIR/plugins.
Изменения core/ui не становятся устойчивыми к обновлению только из-за упаковки в ZIP.

В некоторых manifest PATCH сохранены исторические базы 0.39.x/0.40.0, тогда как общий паспорт проверок относится к 0.40.1.
Следующий паспорт должен различать происхождение модуля и реально проверенные целевые версии. Нельзя просто переписать номер версии и объявить совместимость.

### Порядок реализации и приёмка

| Этап | Результат | Обязательная проверка |
|---|---|---|
| 0. Наши ограничения | Исправлена локальная привязка обучения; определены правила смешанных записей | Фиктивный облачный профиль не получает данные локальных задач; отмена/смена прав отзывают разрешение |
| 1. Один штатный плагин | Один независимый навык/MCP ставится и снимается штатно | ZIP install/remove, настройки, имена MCP, отключение; без личных путей и ключей в пакете |
| 2. Диагностика | CLI читает только разрешённый статус | Неверный токен и команды изменения отклонены; 0 model calls; нет общих событий разговора |
| 3. Контекст и модели | Один явный контракт для всех нужных маршрутов | Нет scope — 0 чтений; чужой revision отклонён; исчезнувший профиль не заменён; локальный режим действует на производные вызовы |
| 4. Кандидат 0.41.0 | Новый оригинал и совместимые адаптеры в отдельной копии | Тесты модулей + новые игры/pins/features + сравнение с чистой базой; сохранение настроек |
| 5. Установка | Проверенный комплект с происхождением и возможностью отката | Backup, штатный выход, post-check, репетиция прерывания/rollback; только потом автоустановка |

Каждый агент берёт один блок и его тесты; один интегратор соединяет изменения. Использовать существующий skill PATCH-010.
Стиль автора: небольшие понятные функции, Python snake_case, существующий JS-стиль, русские комментарии о причинах и ограничениях;
переиспользовать mixins, настройки и UI-компоненты. История изменений — в git/отчёте, не в комментариях к коду.

## ENG

**Design for all modules, integrate one at a time through existing Dewiar mechanisms.** Upstream 0.41.0 already provides plugins, skills, MCP, task delegation/cancellation, task-model selection, lexical Recall and health reporting. Our additions should reuse these services. A thin versioned adapter is still required for model selection, scoped task context, read-only diagnostics and UI integration; the native plugin package is not a general runtime extension loader.

Keep Codex, subscription budgets, external Human Memory and AI20 policies optional. Use the existing AI20 Manager as the execution owner; its live state was not checked. Do not use model-driven scheduled jobs as passive heartbeat. Future contracts must enforce task scope/revision/cancellation and preserve local routing across response, review, translation and learning.

Good small upstream proposals: unique task directories; an explicit error when the assigned model profile is missing; a read-only diagnostic handshake/status command. RU/ENG/CH and Android permission UX have already been proposed in issues #10/#11. Additional context recovery needs a child-result regression before proposing it.

A deterministic offline probe confirms that upstream tasks with the same title in the same minute share a directory and overwrite each other's state; deleting one removes the common directory. Our ID-suffixed path passes. A second synthetic probe finds a gap in our per-task local routing during background reflection: a global profile can be selected. No real network/model request occurred. Fix this and define the policy for mixed traces before promising complete local-only operation.

The release changes 87 files; 7 overlap the 55-file runtime overlay, or 11 across the complete branch. These are overlapping edits, not proven merge conflicts. Preserve new games/pad behavior, feature-setting migration and task pins. Distinguish module origin from verified target versions in manifests. An official installer replaces app files, so copied core/UI changes are not automatically update-safe.

Delivery sequence: fix our routing limitation → one native plugin → read-only diagnostics → provider-independent context/routing contracts → isolated 0.41.0 integration candidate → verified installation/rollback. No new framework is required.

Current evidence: upstream plugin suite 28 checks PASS; our memory/context/observability 69 tests PASS, CLI 12, diagnostics 25, task directory safety 2; existing 0.40.1 overlay verifies 55 files. Integration/build/install on 0.41.0, live models/memory/authentication, physical Android and rollback were NOT_RUN. This document is a plan, not a compatibility certificate or release.

## CH

**设计时考虑所有模块，实施时逐个接入 Dewiar 现有机制。** 原版 0.41.0 已有插件、Skills、MCP、子任务与取消、任务模型选择、词法 Recall 和健康状态。应复用这些功能。模型路由、限定任务范围的上下文、只读诊断和界面接入仍需要轻量、带版本的适配层；现有插件包不是任意运行时代码的加载器。

Codex、订阅配额、外部 Human Memory 和 AI20 策略保持可选。AI20 继续由现有 Manager 管理执行，本次未检查其在线状态。定时模型任务不能充当无模型调用的心跳。未来接口须验证任务范围、版本和取消，并在回答、复查、翻译和学习中保持本地路由。

适合分别向上游提出：任务目录唯一化；已指定模型被删除时明确报错；只读诊断连接与状态命令。语言/语音和 Android 权限界面已提交 #10/#11。额外的上下文恢复还需验证已启动子任务的结果仍可读取。

离线确定性测试确认：原版在同一分钟创建同名任务会共用目录并覆盖状态，删除其中一个会删除共同目录。我们的目录名加入任务 ID 后通过检查。另一合成测试发现，我们的任务级本地绑定在后台学习时可能丢失并选择全局模型。没有实际网络或模型请求。承诺完整本地运行前，必须修复并定义混合学习记录的处理规则。

新版改变 87 个文件，其中 7 个与 55 文件运行时层重叠，完整分支中重叠 11 个；这不等于已确认合并冲突。需保留游戏/记事本、新功能开关的配置迁移和任务置顶。清单须区分模块起源版本与实际验证的目标版本。官方安装器会替换 app 文件，复制进去的 core/UI 改动不会自动保留。

实施顺序：修复我们自己的路由限制 → 一个原生插件 → 只读诊断 → 独立于提供商的上下文/路由契约 → 隔离的 0.41.0 集成候选 → 验证安装和回滚。无需建立第二套框架。

当前结果：原版插件 28 项 PASS；我们的记忆/上下文/观测 69 项、CLI 12 项、诊断 25 项、目录安全 2 项 PASS；旧版 0.40.1 overlay 的 55 文件验证通过。尚未执行 0.41.0 集成构建/安装、实际模型/记忆/登录、物理 Android 或回滚。这是研究和计划，不是兼容认证或正式发布。
