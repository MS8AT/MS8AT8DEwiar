# Простая карта блоков Dewiar

Не нужен новый plugin framework. Каждый контур остаётся обычным небольшим модулем, а связь с Dewiar выполняет тонкий adapter.

| Блок | Одна ответственность | Вход → выход | Автономная проверка |
|---|---|---|---|
| Access | Профиль и разрешения Codex/API | настройки → безопасный snapshot | синтетический профиль, без входа |
| Brains | Выбор модели по роли | роль + доступные профили → ID профиля | таблица маршрутов |
| Memory | Контекст задачи и Human Memory | scope + revision → ограниченный пакет | синтетический MCP-пакет |
| Tasks | Шаги, квота и подзадачи | цель + разрешения → состояние задачи | fake task/manager |
| Observe | Heartbeat, журнал, API/CLI/SLI | безопасный snapshot → JSON | синтетические события |
| Language | `RU / ENG / CH` и голос | язык + пол → правило и voice ID | чистые функции |
| Update | Проверка, backup и rollback | подписанный release → план установки | temp-каталог, без установки |

## Граница интеграции

```text
UI → adapter → один блок → JSON-результат
                    ↓
             локальный журнал
```

- Блок не импортирует UI и не знает всё приложение.
- UI не читает внутренние данные блока напрямую.
- Между блоками передаются маленькие JSON-совместимые словари.
- Сеть, модель, аккаунт, запись и публикация не прячутся внутри getter/status.
- Общий файл Dewiar меняет только интеграционный патч после автономных тестов блоков.

## Работа нескольких агентов

1. Координатор назначает каждому агенту один `PATCH-NNN` и ожидаемый контракт.
2. Агент выполняет `inspect`, меняет только свой каталог и выполняет `test`.
3. Проверяющий получает ZIP и test-output, не историю рассуждений.
4. Интегратор отдельно соединяет принятые блоки с Dewiar и запускает интеграционные тесты.
5. Если два агента хотят менять один общий файл, они не сливают изменения сами: общий adapter становится отдельным интеграционным блоком.

## Порядок выделения из текущего кода

Сначала выделять уже почти независимые контуры: `Language → Observe → Memory → Access → Tasks → Brains → Update`. После каждого шага — отдельный patch, автономный тест и только затем интеграция. Не переписывать всё приложение одним большим изменением.
